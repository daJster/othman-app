# Dev environment (web + Android emulator)

One Metro server (`npm start`, port **8081**) serves the web bundle and the
native dev client at the same time. Both targets hot-reload from the same source
tree, so a change is visible in the browser and on the phone without a rebuild.

```
npm start            # Metro on :8081 (web + native)
npm run phone        # adb reverse + open the dev client on the emulator
open http://localhost:8081   # web
```

## One-time setup

| Piece       | Value on this machine                                   |
| ----------- | ------------------------------------------------------- |
| Android SDK | `%LOCALAPPDATA%\Android\Sdk`                            |
| JDK         | `C:\Program Files\Android\Android Studio\jbr` (Java 25) |
| Emulator    | `Pixel_10` (`emulator-5554`, API 37)                    |

Neither `adb` nor `java` is on `PATH`, so the build needs them injected:

```powershell
$env:JAVA_HOME   = "C:\Program Files\Android\Android Studio\jbr"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:PATH = "$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:PATH"
```

`android/local.properties` already points Gradle at the SDK, so only
`JAVA_HOME` matters for the build itself.

Install the dev client once (first run downloads Gradle + AGP artifacts and
takes 10–20 minutes):

```bash
npm run android:build     # expo run:android --no-bundler
```

The emulator is x86_64 16 KB pages; Expo SDK 58 / RN 0.88 support it. Building
only the emulator ABI keeps rebuilds fast:

```powershell
$env:ORG_GRADLE_PROJECT_reactNativeArchitectures = "x86_64"
```

Expo Go is **not** an option: `@expo/ui` and `expo-glass-effect` have no
Expo Go implementation, and the app imports them on first render.

### Machine-specific fixes already applied

These were needed once and are easy to hit again:

1. **Regenerate `android/` after an SDK bump.** The checked-out native project
   was generated by an older patch release, so Gradle 9.3.1/AGP 9 rejected it
   ("Minimum supported Gradle version is 9.4.1", then "Cannot add extension
   with name 'kotlin'"). `android/` is gitignored (Expo CNG), so:
   `npx expo prebuild --platform android --clean --no-install`.
2. **Upgrade ninja in the SDK.** CMake 3.22.1 ships ninja 1.10.2, which is not
   long-path aware; `react-native-reanimated`'s object paths cross 260 chars and
   the link fails with `ninja: error: mkdir(...) No such file or directory`.
   `Sdk\cmake\3.22.1\bin\ninja.exe` was replaced with **ninja 1.12.1** (original
   kept as `ninja-1.10.2.orig.exe`). Re-apply after an SDK/CMake reinstall.

## Daily loop

```bash
npm start                 # terminal 1: Metro
npm run phone             # terminal 2: reload the app against Metro
```

- **Phone hot reload** — editing a file refreshes the running app.
- **Web** — `http://localhost:8081` in a browser (`npm run web` also opens it).
- **Static web check** — `npm run build:web && npm run preview:web` on :8088.

## Agent helpers

`scripts/dev-phone.mjs` wraps adb so the emulator can be driven without an
interactive terminal:

| Command                | Effect                                                       |
| ---------------------- | ------------------------------------------------------------ |
| `npm run phone`        | `adb reverse tcp:8081` + launch `com.kuttab.othman` at Metro |
| `npm run phone:shot`   | PNG screenshot → `.expo/shots/*.png` (readable by the agent) |
| `npm run phone:reload` | force-stop + relaunch (fresh bundle, bypasses Fast Refresh)  |
| `npm run phone:logs`   | last 200 logcat lines for the app (`--lines N` to change)    |
| `npm run phone:info`   | device, app-installed state, resolved adb path               |

Pass a name to keep a stable screenshot: `node scripts/dev-phone.mjs shot home`.

For the web half, the Playwright MCP server configured in `opencode.jsonc`
drives `http://localhost:8081` directly.

## Mock backend (`server/`, port 9000)

The app can run against a local serverless-shaped API instead of Firebase. It
covers account/meeting/Qur'an CRUD, authentication, authorization, polling and
SSE. Full design and endpoint list: [`server/README.md`](../server/README.md).

```bash
npm run dev          # API on :9000 + Metro on :8081 (web and native)
npm run dev:web      # same, opens the browser
npm run mock         # API only
npm run test:server  # backend integration tests (Node test runner)
```

`npm run dev` sets `EXPO_PUBLIC_MOCK_BACKEND=1` for Metro, which switches the
auth service, meetings/profile/progress repositories onto the mock server. Sign
in with `student@kuttab.test` / `kuttab1234` (or `admin@kuttab.test` for account
administration). The Android emulator reaches the host at `10.0.2.2:9000`
automatically; a physical device needs
`EXPO_PUBLIC_MOCK_API_URL=http://<lan-ip>:9000`.

`npm start` alone still runs the offline fixtures — the two modes are explicit,
never implicit. Stop any Metro already bound to :8081 before `npm run dev`;
otherwise Expo offers the next free port.

## Home demo content

The circle rail, the pinned pill and the notifications sheet all read one demo
store. To change what the landing page shows, edit **one file**:

```
src/data/mock/CircleMock.json      # the rows
src/services/circle/               # types, cache-first service, repository
src/features/home/circle-projection.ts   # which row means what
```

- Dates are **day offsets** (`dayOffset: 0` = today), never fixed dates: a
  fixture pinned to a calendar day starts lying the moment that day passes.
- `kind` is `halqa | exam | notice`; notices carry a `topic`
  (`shaykh | halqa | app`) that becomes the row's overline.
- The **pill** reports the soonest timed row inside 7 days, else the reader's
  saved page. The **rail** asks three different questions (next session, next
  exam, newest notice). The **inbox** is the full list, newest first.
- Read state is per device in `STORAGE_KEYS.homeNotices`; clearing it brings the
  clay dot back.

The hero film is re-encoded, never hand-edited: see `assets/hero/README.md` and
`node scripts/encode-hero.mjs <master> --trim 0.05:4.05`.

## Meetings demo content

`src/data/mock/MeetingsMock.json` follows the same rule — **day offsets, never
fixed dates** — and derives each session's status at read time:

- `dayOffset` is relative to today (0 = today, negative = past).
- `time` is `HH:mm`, `durationMinutes` a number; the card formats both in the
  active language, so Arabic gets ٦:٠٠ م and ٦٠ دقيقة.
- `titleAr / descriptionAr / locationAr / organizerAr` are optional and win in
  Arabic; English is the fallback.
- Status (`soon | upcoming | scheduled | past`) is computed by
  `core/domain/meetings/status.ts`, never stored: a fixture that hard-codes
  "starts soon" starts lying the moment the session ends.
- Attendee portraits are intentionally absent; the stack renders initials.

To change what the calendar shows, edit the JSON only.

## Troubleshooting

- **`adb` not found** — the script resolves the SDK itself; only raw `adb`
  calls need `%LOCALAPPDATA%\Android\Sdk\platform-tools` on `PATH`.
- **App opens to a red screen / "Unable to load script"** — Metro is not
  running or `adb reverse` was lost after an emulator restart; rerun
  `npm run phone`.
- **`INSTALL_FAILED_UPDATE_INCOMPATIBLE`** — the emulator has an app signed
  with another key: `adb uninstall com.kuttab.othman`, then reinstall.
- **Native dependency added** — the dev client must be rebuilt
  (`npm run android:build`); JS-only changes never need it.
- **Emulator cold start** —
  `emulator -avd Pixel_10` from `%LOCALAPPDATA%\Android\Sdk\emulator`, then
  `npm run phone` once `adb devices` lists it.
- **Blank page or `Requiring unknown module "…"` in Metro** — stale cache after
  a prebuild/branch switch: restart with `npx expo start --clear`.
- **Do not run `expo start` with `CI=1`** on this machine: it disables file
  watching, so Fast Refresh silently stops while the server still answers 200.
- **Playwright MCP** is pinned to `--browser chromium` (Chrome is not installed
  here); `npx playwright install chromium` provisions it.

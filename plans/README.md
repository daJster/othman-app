## Execution protocol

- Work on `ui/title` (or a branch cut from it), one plan at a time.
- Read the plan fully, run its drift check, then execute its steps in order.
- Do not stage unrelated environment deletions (`openspec/*`, `.agents/skills/*`,
  `.mcp.json`) or tooling edits (`opencode.jsonc`, `skills-lock.json`) that may
  be present in the working tree.
- A plan is one commit (or one squash); the message names the plan number.
- Update the status row before committing: `IN PROGRESS` when starting,
  `DONE`/`BLOCKED` when finished.
- Final verification for every plan: `npm run verify`; for UI plans also
  `npm run build:web && npm run check:web`; plans 005 and 008 also run
  `npm run e2e:web`.
- Native visual checks are required for plans 001, 004 and 005. If no
  simulator/device is available, mark the plan `DONE` for code and add a
  `BLOCKED` note in the PR evidence for the visual check; do not claim it was
  performed.
